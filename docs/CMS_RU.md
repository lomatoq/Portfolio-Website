# Управление портфолио

## Запуск

Из корня `github-portfolio` запустите:

```powershell
python cms_server.py
```

Откройте `http://127.0.0.1:8765/admin/`. Сервер доступен только на этом компьютере (`127.0.0.1`). Публичный сайт по-прежнему статический: панель сохраняет `content/cms.json`, а затем запускает `rebuild.py`, который обновляет `index.html`. Для публикации нужно отправить изменения репозитория в `main`; GitHub Pages развернёт их обычным способом. Без запущенного локального сервера публичная страница `/admin/` не может сохранять данные.

## Что редактируется

- **Проекты:** существующие кейсы и новые личные/рабочие проекты, название, тип, описание, роль, материалы, теги, статус, порядок, видимость и размещение. Новые проекты появляются в каталоге или галерее мини-проектов. Рабочий проект можно привязать к существующей компании: он появится и внутри её карточки в истории работы. Опция «Показывать в избранном» добавляет проект в отдельный раздел избранного. Пять существующих интерактивных глав сохраняют свою сцену и редактируются во вкладке «Избранные главы».
- **Структура проектов:** слева проекты собраны в дерево: «Личные проекты» → «Избранные проекты» / «Другие проекты» и «Работа · компании» → конкретная компания → проекты. Работы без привязки находятся в ветке «Без компании». У каждой ветки есть «Добавить сюда»: новый проект сразу получает нужную группу и компанию. Кнопка «＋» у заголовка добавляет проект в ветку выбранного проекта. В редакторе над названием показан полный путь. Поиск находит проекты и компании; ветки можно сворачивать. Кнопки «Выше» и «Ниже» меняют порядок проектов только внутри их ветки.
- **Медиа проекта:** неограниченный в рамках редактора набор упорядоченных блоков изображения, видео и текста. Изображения сохраняют собственное соотношение сторон в медиапросмотре. Для каждого файла можно указать подпись и описание. Видео допускает WebM и отдельный MP4 как запасной источник, а также постер.
- **Слайды глав:** редактирование подписей исходных слайдов, замена слайда изображением или видео, добавление, удаление и порядок. Навигационные точки и счётчик пересобираются автоматически.
- **Тексты сайта:** основные заголовки и вступления разделов.

После изменений нажмите **Сохранить сайт**. **Просмотр** автоматически сохранит изменения и откроет сайт в новой вкладке. `Ctrl+S` / `⌘S` тоже сохраняет. Несохранённые изменения отмечаются в шапке. Редактор предупреждает при закрытии вкладки с несохранёнными правками.

## Форматы

JPEG/PNG автоматически переводятся браузером в WebP с качеством 0.84 и ограничением 2560 px по ширине и 14000 px по высоте. Готовый WebP загружается как есть. Размеры записываются в контент, чтобы браузер резервировал место до загрузки. Для очень длинной истории лучше создать несколько блоков: их можно переставлять без изменения шаблона.

Видео загружается без перекодирования. Используйте WebM (например, VP9) как основной файл и H.264 MP4 как запасной вариант для максимальной совместимости. Размер одного файла ограничен 200 МБ. Для мобильного просмотра лучше подготовить разумное разрешение и короткие клипы. Загрузка не отправляет файлы внешнему сервису: они попадают в `assets/uploads/` и публикуются вместе с сайтом после push.

## Безопасность и восстановление

Панель принимает изменения только с того же локального адреса. При одновременном редактировании она не перезапишет данные, изменённые на диске после открытия вкладки: предложит перезагрузить страницу. Удаление проекта в панели доступно только для проектов, добавленных через неё; существующие кейсы можно скрыть. Загруженные файлы не удаляются автоматически при удалении блока, чтобы случайно не сломать опубликованный контент. Они остаются в `assets/uploads/` до ручной очистки. История изменений хранится в Git.

## Техническое устройство

`content/cms.json` — единственный редактируемый источник данных панели. `src/cms-runtime.js` применяет его к статической странице до запуска режиссёра прокрутки, а `src/media-viewer.js` выводит медиа и текстовые блоки. `rebuild.py` встраивает данные и исходники в `index.html`, сохраняя возможность открыть портфолио без сервера. `tools/init_cms.py` использовался для однократного переноса старых проектов; повторный запуск требует явного `--force`, потому что он сбрасывает данные редактора.
