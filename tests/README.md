# Проверки портфолио

## Текущая версия FLOW64

`node tests/safari64.cjs` проверяет Chromium и WebKit с touch/DPR 3: исходное GPU-стекло, кэш свечения десяти букв, покрытие viewport маской, градиент и premultiplied alpha, ограниченный слой зерна и объединение изменений высоты. `QA_DIR` включает скриншоты. Старый `safari63.cjs` перенаправляет на этот тест.

`BASELINE_HTML` и необязательный `RESULT_JSON` для `node tests/performance64.cjs` задают A/B сравнение первого экрана в настольном WebKit при одинаковых шрифтах и качестве. Запускать отдельно от других браузерных тестов. Это не FPS iPhone. Результаты: [FLOW64](../docs/FLOW64_RENDERING_RU.md).

Сохраняются регрессионные проверки FLOW62:

Проверки работают с собранным `index.html` через статический сервер. Нужны Node.js, пакет `playwright`, установленный Google Chrome (`channel: chrome`), для `render61.cjs` также браузер Playwright WebKit. `FLOW59_URL` задаёт адрес сайта, по умолчанию `http://127.0.0.1:4192/`.

- `flow62.cjs`: входы во все главы, отсутствие паузы после раскрытия, разворот, быстрый проход, свободная галерея, нативное завершение входа после touch, вложенные слои. Размеры 1440×844, 390×844 и 844×390.
- `hero62.cjs`: настоящий pointer trail, размещение световой ленты, пиксельные пробы инверсии и запуск полёта первого проекта по наведению. Пробы инверсии нужно просмотреть, проверка одних CSS-свойств недостаточна.
- `media62.cjs`: длинное изображение и заголовок, внутренний скролл, клавиатура и фокус, rapid reopen, видео, возврат, локальная подмена в режиме автора, reduced motion. Размеры 320×844 и 1440×844.
- `performance62.cjs`: первый экран, GPU timer queries и отдельная трасса JS/style/paint. Нужен `BASELINE_HTML`. Параметры `WIDTHS`, `VARIANTS`, `SAMPLES`, `WARMUP_MS`, `RESULT_JSON` позволяют повторить и сохранить замер. Пример обратного порядка: `VARIANTS=current,baseline,baseline,current`. Не запускать другие браузерные тесты одновременно с замером.
- `touch60.cjs` и `render61.cjs`: дополнительные проверки нативных свайпов, WebGL 1/2, WebGL 1 без VAO и WebKit.
- `visual61.cjs`: контрольные пары кадров; нужны `BASELINE_HTML`, по желанию `RESULTS_DIR`, `WIDTHS`, `SCENES=top,playgendary,vice,vice:0:0,elemental`. CSS, SVG и видео фиксируются по времени. `compare61.py` остаётся строгим сравнением с порогом 1/255: ожидаемое восстановление инверсии требует отдельного осмотра, порог не расширяется ради зелёного результата.

Результаты и ограничения: [FLOW62](../docs/FLOW62_PERFORMANCE_RU.md). Скриншоты `flow62.cjs` / `hero62.cjs` по умолчанию сохраняются в соседний каталог `../mobile61-qa/flow62`.

## Исторические проверки FLOW58–61

Ниже — описание прежних релизов. Ожидания старого захвата прокрутки в FLOW59 и растровой demo-картинки в media58/edge58 не являются контрактом FLOW62. Для текущих переходов и нового viewer используйте проверки выше.

Новые проверки производительности и рендера FLOW61 описаны в [отчёте](../docs/FLOW61_PERFORMANCE_RU.md). `performance61.cjs` измеряет CPU и вызовы WebGL, `render61.cjs` проверяет WebGL 1/2 и WebKit, `visual61.cjs` создаёт пары кадров. Сравнение: `python tests/compare61.py <папка кадров>` (Pillow). Для `visual61.cjs` нужен `BASELINE_HTML`; `RESULTS_DIR` задаёт каталог результатов.

Проверки относятся к полному `index.html`. Это отдельные классы тестов, не рекламная сумма «всех пройденных браузерных тестов».

## Что запускается

`smoke58.py` — 1440×900: одиночный сильный input на входе, полная первая сцена, следующий wheel без ожидания, доведение без возврата к покинутому интро, ввод во время анимации, несколько карточек за серию wheel, непрерывная история работы.

`interaction58.py` — 1366×768: реальные wheel-входы во все пять проектов, изменение позиции за два предъявленных кадра после следующего input, видимая реакция первого экрана, разворот, horizontal drag, повторная клавиатура, нативное изменение позиции и возобновление управления. Между независимыми сценариями применяется instant placement; это не один непрерывный проход всего сайта.

`poses58.py WIDTH HEIGHT` — статическая геометрия и вычисленные стили всех интро и карточек. Использует мгновенную установку позиции, не измеряет переходы. Релизные отчёты: 1366×768 и 390×844.

`media58.py` — обычные и media-ячейки внутри компании; tall image, отдельный scroll, Escape, воспроизведение и сохранение пути обычного вложенного кейса.

`mobile58.py` — 390×844, mobile/touch emulation: вертикальный touch через CDP, media viewport, порядок картинки и текста, появление notes в конце, блокировка фонового scroll, возврат в кейс, inline autoplay.

`edge58.py` — focus, локальная замена изображения, rapid close/reopen, backdrop close, пауза видео, восстановление overflow, изменение viewport с двумя открытыми слоями, refit parent-case, reduced motion.

`kinematics58.cjs` извлекает настоящую функцию springStep из источника: постоянный target на 30/60/120/144 Hz, monotone approach, continuity при смене цели, разворот, синтаксис JS. Это математические проверки, не FPS benchmark.

`renderers58.py fallback|webgl` — диагностика реального режима рендера и простой scroll smoke. Запрошенный WebGL в этой среде не создал контекст: результат помечен как **blocked_environment**, не как успешно проверенный WebGL.

## Повторный запуск

Для проверки сайта зависимости не нужны. Только для повторного запуска тестов потребуются Python 3.10+, Playwright, Chromium и Node.js:

```sh
python -m pip install playwright
python -m playwright install chromium
```

По умолчанию используется `/usr/bin/chromium`. Укажите `CHROMIUM_PATH=playwright`, чтобы использовать браузер Playwright, или полный путь к Chromium. Например, в PowerShell:

```powershell
$env:CHROMIUM_PATH = "playwright"
python tests/smoke58.py
python tests/interaction58.py
python tests/poses58.py 1366 768
python tests/poses58.py 390 844
python tests/media58.py
python tests/mobile58.py
python tests/edge58.py
node tests/kinematics58.cjs
```

## Ограничения и интерпретация

Проверялось полное содержимое HTML через `set_content`; file:// запрещён политикой тестового Chromium. Внешние запросы шрифтов блокировались ради воспроизводимости. Новые runtime assets встроены; финальная упаковка и соответствие исходников HTML проверяются отдельно.

Колесо и touch подаются через Playwright/CDP, но это не физическая мышь или трекпад. Часть кнопок в интеграционных тестах активируется DOM click, а мобильное закрытие дополнительно — touch tap. Последовательный ввод в медленном headless renderer не измеряет частоту реального трекпада. Проверка двух предъявленных кадров подтверждает отсутствие логического ожидания, а не заданную задержку в миллисекундах на любом устройстве.

Рендер в этой среде использовал Canvas 2D fallback. Аппаратный WebGL, настоящий iOS/Safari, разные wheel-драйверы и FPS на пользовательском компьютере не проверены. Скриншоты подтверждают раскладку и позы, но не субъективную плавность физического взаимодействия.
